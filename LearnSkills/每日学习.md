📚 Java 基础 (约 20 题)

1.  == 和 equals() 的区别？在 Android 中有何应用？
    ◦   == 比较对象内存地址；equals() 默认比较地址，但可被重写以比较内容。

    ◦   Android 应用：比较字符串内容用 equals()；单例模式判断实例用 ==。

2.  final 关键字的用法？
    ◦   修饰类：不可被继承。

    ◦   修饰方法：不可被重写。

    ◦   修饰变量：基本类型值不可变；引用类型引用不可变（对象内容可变）。

3.  static 关键字的用法？
    ◦   修饰变量/方法：属于类，而非实例，在类加载时初始化。

    ◦   修饰代码块：类加载时执行一次，用于初始化静态资源。

    ◦   注意：静态变量生命周期长，不当持有 Context 易导致内存泄漏。

4.  抽象类与接口的区别？
    ◦   抽象类：用于代码复用，可包含抽象和具体方法，单继承。

    ◦   接口：用于行为契约，只含抽象方法（Java 8后可有默认/静态方法），多实现。

    ◦   Android 场景：Activity/Fragment 继承 AppCompatActivity (抽象类)；实现 View.OnClickListener 接口 (行为)。

5.  Java 异常体系？Error 和 Exception 的区别？
    ◦   Throwable 是所有错误和异常的超类。

    ◦   Error：严重系统错误（如 OutOfMemoryError），程序通常无法处理。

    ◦   Exception：程序可处理的异常，分为检查型 (IOException) 和非检查型 (RuntimeException)。

6.  String、StringBuilder、StringBuffer 的区别？
    ◦   String：不可变，频繁拼接会产生大量中间对象，性能差。

    ◦   StringBuilder：可变，非线程安全，单线程下性能最优。

    ◦   StringBuffer：可变，线程安全，性能略低于 StringBuilder。

7.  HashMap 的实现原理？
    ◦   基于数组+链表/红黑树实现。通过 key 的 hashCode() 计算数组下标，解决哈希冲突使用链地址法。

    ◦   当链表长度超过阈值（默认8）且数组容量不小于64时，链表会转换为红黑树，以优化查询性能。

8.  ConcurrentHashMap 如何保证线程安全？
    ◦   JDK 1.7：采用 Segment 分段锁，锁的粒度较粗。

    ◦   JDK 1.8：摒弃 Segment，改用 synchronized + CAS 锁单个数组元素（Node），锁粒度更细，并引入红黑树优化。

9.  synchronized 和 volatile 的区别？
    ◦   synchronized：保证原子性和可见性，可修饰方法或代码块，是悲观锁。

    ◦   volatile：仅保证可见性和有序性（禁止指令重排），不保证原子性，适用于状态标志位。

10. Java 四种引用类型及使用场景？
    ◦   强引用：默认，GC 永不回收，可能导致内存泄漏。

    ◦   软引用：内存不足时 GC 回收，适合做缓存。

    ◦   弱引用：每次 GC 都可能回收，常用于 WeakReference<Context> 避免内存泄漏。

    ◦   虚引用：配合引用队列，用于跟踪对象被回收的状态。

11. Java 内存模型 (JMM) 与 volatile 的内存语义？
    ◦   JMM 定义了线程和主内存之间的抽象关系，通过 happens-before 原则保证可见性。

    ◦   volatile 变量的写操作会立即刷新到主内存，读操作会从主内存重新加载，从而保证了变量的可见性。

12. wait() / notify() / notifyAll() 的用法与原理？
    ◦   必须在 synchronized 代码块或方法中调用。

    ◦   wait()：释放锁并进入等待队列。

    ◦   notify() / notifyAll()：唤醒等待队列中的一个或所有线程。

    ◦   典型应用：生产者-消费者模型。

13. Java 线程池的核心参数与工作流程？
    ◦   核心参数：核心线程数、最大线程数、存活时间、工作队列、线程工厂、拒绝策略。

    ◦   工作流程：任务提交后，先创建核心线程；核心线程满后，任务进入队列；队列满后，创建非核心线程；线程数达到最大值后，执行拒绝策略。

14. ThreadLocal 的原理与内存泄漏风险？
    ◦   为每个线程提供独立的变量副本，实现线程隔离。

    ◦   内存泄漏风险：ThreadLocalMap 的 Entry 对 ThreadLocal 是弱引用，但对 value 是强引用。若 ThreadLocal 外部引用被置为 null，Entry 的 key 会变为 null，但 value 仍存在，导致内存泄漏。因此，使用完毕后务必调用 remove() 方法。

20. 简述 Java 垃圾回收 (GC) 机制？
    ◦   判断算法：引用计数法（有循环引用问题）和可达性分析（根搜索算法，主流）。

    ◦   回收算法：标记-清除、标记-整理、复制算法。现代 JVM 通常采用分代收集策略（新生代用复制，老年代用标记-整理/清除）。

🚀 Kotlin 基础 (约 15 题)

1.  val 和 var 的区别？
    ◦   val (value)：只读变量，只能被赋值一次，对应 Java 的 final 变量。

    ◦   var (variable)：可变变量，可以被多次赋值。

2.  Kotlin 的空安全机制？
    ◦   类型系统区分可空 (String?) 和非空 (String) 类型。

    ◦   访问可空类型时，必须使用安全调用 (?.)、Elvis 操作符 (?:) 或非空断言 (!!.)。

3.  object 关键字的作用？
    ◦   对象声明：创建单例。

    ◦   伴生对象：类似 Java 的静态成员容器。

    ◦   匿名对象：用于实现接口或继承类的一次性对象。

4.  data class 的特点？
    ◦   自动生成 equals()、hashCode()、toString()、copy() 和 componentN() 函数，极大简化了数据模型的编写。

5.  sealed class 和 enum 的区别？
    ◦   enum：实例数量固定。

    ◦   sealed class：子类数量有限但可在不同文件中定义，更适合表示层次化的结果或状态。

6.  Kotlin 中 == 和 === 的区别？
    ◦   ==：调用 equals() 方法，比较内容。

    ◦   ===：比较对象引用（内存地址）。

7.  inline 和 noinline 的作用？
    ◦   inline：将函数体内联到调用处，减少函数调用开销，尤其适合高阶函数。

    ◦   noinline：用于标记 inline 函数中的某个 Lambda 参数不进行内联。

8.  reified 关键字的作用？
    ◦   与 inline 配合使用，允许在泛型函数内部访问泛型的实际类型 T，解决了 Java 泛型擦除的问题。常用于简化 Retrofit 和 Gson 的调用。

9.  Kotlin 作用域函数 (let, run, apply, also) 的区别？
    ◦   共同点：都提供作用域，避免创建临时变量。

    ◦   let：返回 Lambda 的最后一行，适合对对象进行转换或链式调用。

    ◦   run：返回 Lambda 的最后一行，适合对一个对象执行多个操作并获取结果。

    ◦   apply：返回调用对象本身，适合对象的初始化配置。

    ◦   also：返回调用对象本身，适合执行一些附加的副作用操作（如日志打印）。

10. Kotlin 协程与 Java 线程的区别？
    ◦   协程：轻量级“用户态线程”，由 Kotlin 运行时管理，开销远小于 OS 线程。通过 suspend 函数实现非阻塞式挂起，不占用线程资源。

    ◦   线程：OS 级别的资源，创建和切换开销较大。

11. launch 和 async 的区别？
    ◦   launch：启动一个不会返回结果的协程，用于执行没有返回值的异步任务。

    ◦   async：启动一个会返回 Deferred<T> 对象的协程，通过 await() 获取结果，用于并发执行多个任务并等待它们完成。

12. CoroutineScope 的作用？
    ◦   定义协程的作用域和生命周期。它关联一个 Job 对象，当 Job 被取消时，其范围内的所有协程都会被取消。

    ◦   Android 中常用的作用域有 lifecycleScope (绑定 Activity/Fragment 生命周期) 和 viewModelScope (绑定 ViewModel 生命周期)。

13. suspend 关键字的作用？
    ◦   标记一个函数为挂起函数，它只能在协程或其他挂起函数中被调用。

    ◦   挂起函数不会阻塞线程，而是将协程的执行挂起，待异步操作完成后再恢复执行。

14. Flow 与 LiveData 的区别？
    ◦   Flow：冷数据流，遵循“订阅-发射”模式，支持丰富的操作符（如 map, filter），更适合处理复杂的异步数据流。

    ◦   LiveData：热数据持有者，具有生命周期感知能力，能自动在 UI 组件销毁时停止数据分发，避免内存泄漏，是 Jetpack 架构组件的一部分。

15. Kotlin 属性委托 (by lazy, by viewModels)？
    ◦   by lazy：实现懒加载，属性在第一次被访问时才会初始化。

    ◦   by viewModels()：由 Hilt 或 Jetpack 提供，用于自动创建并注入 ViewModel 实例，简化依赖管理。

🌐 网络编程 (约 15 题)

1.  HTTP 1.0、1.1、2.0 的主要区别？
    ◦   1.0：每次请求都需要建立 TCP 连接，开销大。

    ◦   1.1：默认开启持久连接 (Keep-Alive)，支持管道化请求，但队头阻塞问题依然存在。

    ◦   2.0：采用二进制分帧层，支持多路复用、头部压缩和服务器推送，性能大幅提升。

2.  GET 和 POST 的区别？
    ◦   GET：请求参数附加在 URL 后，有长度限制，可被缓存，幂等且安全（不修改服务器状态）。

    ◦   POST：请求参数在请求体中，无长度限制，不会被缓存，非幂等且不安全（可能修改服务器状态）。

3.  TCP 三次握手和四次挥手的过程？
    ◦   三次握手 (建立连接)：

        1.  客户端 -> 服务器：SYN=1, seq=x
        2.  服务器 -> 客户端：SYN=1, ACK=1, seq=y, ack=x+1
        3.  客户端 -> 服务器：ACK=1, seq=x+1, ack=y+1
    ◦   四次挥手 (断开连接)：

        1.  主动方 -> 被动方：FIN=1, seq=u
        2.  被动方 -> 主动方：ACK=1, seq=v, ack=u+1
        3.  被动方 -> 主动方：FIN=1, ACK=1, seq=w, ack=u+1
        4.  主动方 -> 被动方：ACK=1, seq=u+1, ack=w+1

4.  HTTPS 的工作流程？
    ◦   在 TCP 三次握手之后，增加了一个 TLS/SSL 握手过程：

        1.  客户端发送 ClientHello，包含支持的加密套件等信息。
        2.  服务器响应 ServerHello，确定加密套件，并返回其数字证书。
        3.  客户端验证证书的有效性。
        4.  双方协商出一个会话密钥，用于后续通信的对称加密。

5.  OkHttp 的核心组件？
    ◦   OkHttpClient：配置请求的客户端实例。

    ◦   Request：封装请求的 URL、方法、头信息等。

    ◦   Response：封装服务器返回的响应数据。

    ◦   Interceptor：拦截器链，用于实现日志、缓存、认证等横切关注点。

6.  OkHttp 的拦截器原理？
    ◦   采用责任链模式。请求从第一个拦截器开始，依次经过 application interceptor -> network interceptor，最终到达服务器。响应则沿原路返回，依次经过 network interceptor -> application interceptor。

7.  Retrofit 的工作原理？
    ◦   基于 OkHttp，通过动态代理和注解将 Java/Kotlin 接口转换为网络请求。

    ◦   在编译期，Retrofit 会解析接口方法上的注解，生成具体的网络请求代码。

8. 如何封装一个健壮的网络层？
   ◦   统一入口：使用单例 OkHttpClient 和 Retrofit 实例。

   ◦   数据转换：使用 ConverterFactory (如 Gson) 自动序列化/反序列化。

   ◦   错误处理：定义统一的 Result<T> 或 Sealed Class 来封装成功和失败状态。

   ◦   拦截器：添加日志、公共请求头、缓存、Token 刷新等拦截器。

   ◦   协程：在 ViewModel 中使用 viewModelScope 发起网络请求，确保生命周期安全。

9. Android 中常见的网络缓存策略？
   ◦   HTTP 缓存：通过 Cache-Control、ETag、Last-Modified 等响应头控制。

   ◦   OkHttp 缓存：配置 Cache 对象，将响应缓存到磁盘。

   ◦   本地数据库：使用 Room 等将网络数据持久化，实现离线访问。

10. 如何取消一个网络请求？
    ◦   OkHttp：通过 Call.cancel() 取消请求。

    ◦   Retrofit + 协程：协程绑定 viewModelScope 或 lifecycleScope，当组件销毁时，协程会自动取消，从而取消内部的网络请求。

11. WebSocket 与 HTTP 的区别？
    ◦   HTTP：请求-响应模式，通信由客户端主动发起，服务器被动响应。

    ◦   WebSocket：全双工通信协议，在 TCP 握手后，连接保持打开状态，双方可随时互相发送数据，适合实时聊天、推送等场景。

12. DNS 解析过程？
    1.  检查浏览器缓存。
    2.  检查操作系统缓存。
    3.  向配置的 DNS 服务器发送查询请求（可递归或迭代查询）。
    4.  获取域名对应的 IP 地址。

13. TCP 拥塞控制算法有哪些？
    ◦   慢启动：指数级增加拥塞窗口。

    ◦   拥塞避免：线性增加

    ◦   工作流程：任务提交后，先创建核心线程；核心线程满后，任务进入队列；队列满后，创建非核心线程；线程数达到最大值后，执行拒绝策略。

14. ThreadLocal 的原理与内存泄漏风险？
    ◦   为每个线程提供独立的变量副本，实现线程隔离。

    ◦   内存泄漏风险：ThreadLocalMap 的 Entry 对 ThreadLocal 是弱引用，但对 value 是强引用。若 ThreadLocal 外部引用被置为 null，Entry 的 key 会变为 null，但 value 仍存在，导致内存泄漏。因此，使用完毕后务必调用 remove() 方法。

15. 强引用、软引用、弱引用、虚引用的区别？
    ◦   强引用：默认，GC 永不回收，可能导致内存泄漏。

    ◦   软引用：内存不足时 GC 回收，适合做缓存。

    ◦   弱引用：每次 GC 都可能回收，常用于 WeakReference<Context> 避免内存泄漏。

    ◦   虚引用：配合引用队列，用于跟踪对象被回收的状态。

16. Java 内存模型 (JMM) 与 volatile 的内存语义？
    ◦   JMM 定义了线程和主内存之间的抽象关系，通过 happens-before 原则保证可见性。

    ◦   volatile 变量的写操作会立即刷新到主内存，读操作会从主内存重新加载，从而保证了变量的可见性。

17. wait() / notify() / notifyAll() 的用法与原理？
    ◦   必须在 synchronized 代码块或方法中调用。

    ◦   wait()：释放锁并进入等待队列。

    ◦   notify() / notifyAll()：唤醒等待队列中的一个或所有线程。

    ◦   典型应用：生产者-消费者模型。

18. Java 线程池的核心参数与工作流程？
    ◦   核心参数：核心线程数、最大线程数、存活时间、工作队列、线程工厂、拒绝策略。

    ◦   工作流程：任务提交后，先创建核心线程；核心线程满后，任务进入队列；队列满后，创建非核心线程；线程数达到最大值后，执行拒绝策略。

19. ThreadLocal 的原理与内存泄漏风险？
    ◦   为每个线程提供独立的变量副本，实现线程隔离。

    ◦   内存泄漏风险：ThreadLocalMap 的 Entry 对 ThreadLocal 是弱引用，但对 value 是强引用。若 ThreadLocal 外部引用被置为 null，Entry 的 key 会变为 null，但 value 仍存在，导致内存泄漏。因此，使用完毕后务必调用 remove() 方法。

20. 简述 Java 垃圾回收 (GC) 机制？
    ◦   判断算法：引用计数法（有循环引用问题）和可达性分析（根搜索算法，主流）。

    ◦   回收算法：标记-清除、标记-整理、复制算法。现代 JVM 通常采用分代收集策略（新生代用复制，老年代用标记-整理/清除）。

🚀 Kotlin 基础 (约 15 题)

1.  val 和 var 的区别？
    ◦   val (value)：只读变量，只能被赋值一次，对应 Java 的 final 变量。

    ◦   var (variable)：可变变量，可以被多次赋值。

2.  Kotlin 的空安全机制？
    ◦   类型系统区分可空 (String?) 和非空 (String) 类型。

    ◦   访问可空类型时，必须使用安全调用 (?.)、Elvis 操作符 (?:) 或非空断言 (!!.)。

3.  object 关键字的作用？
    ◦   对象声明：创建单例。

    ◦   伴生对象：类似 Java 的静态成员容器。

    ◦   匿名对象：用于实现接口或继承类的一次性对象。

4.  data class 的特点？
    ◦   自动生成 equals()、hashCode()、toString()、copy() 和 componentN() 函数，极大简化了数据模型的编写。

5.  sealed class 和 enum 的区别？
    ◦   enum：实例数量固定。

    ◦   sealed class：子类数量有限但可在不同文件中定义，更适合表示层次化的结果或状态。

6.  Kotlin 中 == 和 === 的区别？
    ◦   ==：调用 equals() 方法，比较内容。

    ◦   ===：比较对象引用（内存地址）。

7.  inline 和 noinline 的作用？
    ◦   inline：将函数体内联到调用处，减少函数调用开销，尤其适合高阶函数。

    ◦   noinline：用于标记 inline 函数中的某个 Lambda 参数不进行内联。

8.  reified 关键字的作用？
    ◦   与 inline 配合使用，允许在泛型函数内部访问泛型的实际类型 T，解决了 Java 泛型擦除的问题。常用于简化 Retrofit 和 Gson 的调用。

9.  Kotlin 作用域函数 (let, run, apply, also) 的区别？
    ◦   共同点：都提供作用域，避免创建临时变量。

    ◦   let：返回 Lambda 的最后一行，适合对对象进行转换或链式调用。

    ◦   run：返回 Lambda 的最后一行，适合对一个对象执行多个操作并获取结果。

    ◦   apply：返回调用对象本身，适合对象的初始化配置。

    ◦   also：返回调用对象本身，适合执行一些附加的副作用操作（如日志打印）。

10. Kotlin 协程与 Java 线程的区别？
    ◦   协程：轻量级“用户态线程”，由 Kotlin 运行时管理，开销远小于 OS 线程。通过 suspend 函数实现非阻塞式挂起，不占用线程资源。

    ◦   线程：OS 级别的资源，创建和切换开销较大。

11. launch 和 async 的区别？
    ◦   launch：启动一个不会返回结果的协程，用于执行没有返回值的异步任务。

    ◦   async：启动一个会返回 Deferred<T> 对象的协程，通过 await() 获取结果，用于并发执行多个任务并等待它们完成。

12. CoroutineScope 的作用？
    ◦   定义协程的作用域和生命周期。它关联一个 Job 对象，当 Job 被取消时，其范围内的所有协程都会被取消。

    ◦   Android 中常用的作用域有 lifecycleScope (绑定 Activity/Fragment 生命周期) 和 viewModelScope (绑定 ViewModel 生命周期)。

13. suspend 关键字的作用？
    ◦   标记一个函数为挂起函数，它只能在协程或其他挂起函数中被调用。

    ◦   挂起函数不会阻塞线程，而是将协程的执行挂起，待异步操作完成后再恢复执行。

14. Flow 与 LiveData 的区别？
    ◦   Flow：冷数据流，遵循“订阅-发射”模式，支持丰富的操作符（如 map, filter），更适合处理复杂的异步数据流。

    ◦   LiveData：热数据持有者，具有生命周期感知能力，能自动在 UI 组件销毁时停止数据分发，避免内存泄漏，是 Jetpack 架构组件的一部分。

15. Kotlin 属性委托 (by lazy, by viewModels)？
    ◦   by lazy：实现懒加载，属性在第一次被访问时才会初始化。

    ◦   by viewModels()：由 Hilt 或 Jetpack 提供，用于自动创建并注入 ViewModel 实例，简化依赖管理。

🌐 网络编程 (约 15 题)

1.  HTTP 1.0、1.1、2.0 的主要区别？
    ◦   1.0：每次请求都需要建立 TCP 连接，开销大。

    ◦   1.1：默认开启持久连接 (Keep-Alive)，支持管道化请求，但队头阻塞问题依然存在。

    ◦   2.0：采用二进制分帧层，支持多路复用、头部压缩和服务器推送，性能大幅提升。

2.  GET 和 POST 的区别？
    ◦   GET：请求参数附加在 URL 后，有长度限制，可被缓存，幂等且安全（不修改服务器状态）。

    ◦   POST：请求参数在请求体中，无长度限制，不会被缓存，非幂等且不安全（可能修改服务器状态）。

3.  TCP 三次握手和四次挥手的过程？
    ◦   三次握手 (建立连接)：

        1.  客户端 -> 服务器：SYN=1, seq=x
        2.  服务器 -> 客户端：SYN=1, ACK=1, seq=y, ack=x+1
        3.  客户端 -> 服务器：ACK=1, seq=x+1, ack=y+1
    ◦   四次挥手 (断开连接)：

        1.  主动方 -> 被动方：FIN=1, seq=u
        2.  被动方 -> 主动方：ACK=1, seq=v, ack=u+1
        3.  被动方 -> 主动方：FIN=1, ACK=1, seq=w, ack=u+1
        4.  主动方 -> 被动方：ACK=1, seq=u+1, ack=w+1

4.  HTTPS 的工作流程？
    ◦   在 TCP 三次握手之后，增加了一个 TLS/SSL 握手过程：

        1.  客户端发送 ClientHello，包含支持的加密套件等信息。
        2.  服务器响应 ServerHello，确定加密套件，并返回其数字证书。
        3.  客户端验证证书的有效性。
        4.  双方协商出一个会话密钥，用于后续通信的对称加密。

5.  OkHttp 的核心组件？
    ◦   OkHttpClient：配置请求的客户端实例。

    ◦   Request：封装请求的 URL、方法、头信息等。

    ◦   Response：封装服务器返回的响应数据。

    ◦   Interceptor：拦截器链，用于实现日志、缓存、认证等横切关注点。

6.  OkHttp 的拦截器原理？
    ◦   采用责任链模式。请求从第一个拦截器开始，依次经过 application interceptor -> network interceptor，最终到达服务器。响应则沿原路返回，依次经过 network interceptor -> application interceptor。

7.  Retrofit 的工作原理？
    ◦   基于 OkHttp，通过动态代理和注解将 Java/Kotlin 接口转换为网络请求。

    ◦   在编译期，Retrofit 会解析接口方法上的注解，生成具体的网络请求代码。

8. 如何封装一个健壮的网络层？
   ◦   统一入口：使用单例 OkHttpClient 和 Retrofit 实例。

   ◦   数据转换：使用 ConverterFactory (如 Gson) 自动序列化/反序列化。

   ◦   错误处理：定义统一的 Result<T> 或 Sealed Class 来封装成功和失败状态。

   ◦   拦截器：添加日志、公共请求头、缓存、Token 刷新等拦截器。

   ◦   协程：在 ViewModel 中使用 viewModelScope 发起网络请求，确保生命周期安全。

9. Android 中常见的网络缓存策略？
   ◦   HTTP 缓存：通过 Cache-Control、ETag、Last-Modified 等响应头控制。

   ◦   OkHttp 缓存：配置 Cache 对象，将响应缓存到磁盘。

   ◦   本地数据库：使用 Room 等将网络数据持久化，实现离线访问。

10. 如何取消一个网络请求？
    ◦   OkHttp：通过 Call.cancel() 取消请求。

    ◦   Retrofit + 协程：协程绑定 viewModelScope 或 lifecycleScope，当组件销毁时，协程会自动取消，从而取消内部的网络请求。

11. WebSocket 与 HTTP 的区别？
    ◦   HTTP：请求-响应模式，通信由客户端主动发起，服务器被动响应。

    ◦   WebSocket：全双工通信协议，在 TCP 握手后，连接保持打开状态，双方可随时互相发送数据，适合实时聊天、推送等场景。

12. DNS 解析过程？
    1.  检查浏览器缓存。
    2.  检查操作系统缓存。
    3.  向配置的 DNS 服务器发送查询请求（可递归或迭代查询）。
    4.  获取域名对应的 IP 地址。
